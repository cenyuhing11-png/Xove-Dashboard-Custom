# 统一进程创建入口

## 范围

顶部导航保持：首页 / 进程 / 收件箱 / 新建日记 / 新建任务 / 新建进程 / 更多工具。
首页、进程和收件箱都直接打开 `UnifiedProcessModal`，不再先打开类型菜单。
内部 `project` action 与翻译 key 保留兼容，用户可见标签改为新建进程。

删除了梦序进程左栏创建按钮、日历日期详情创建按钮、学习/项目二级菜单、
月/周日历双击创建监听器、首页空学习卡创建入口、学习主题列表创建工具栏。
原作者工具中的 legacy 项目/任务操作、学习资源操作、收件箱操作不在本次清理范围内。

## 唯一表单与两个创建器

复用原 `ad-task-modal` / `ad-modal-*` 外壳和 `ad-prio-group` 类型按钮，不新增 CSS。
公共字段：名称、可选方向、状态、可选开始/截止日期、可选目标。
学习显示学习名称、所属能力（可选）、学习目标（可选）；项目显示项目名称、项目目标（可选），不显示能力。
切换类型保留尚未提交的公共字段；保存时防止重复提交，同名内容不覆盖。

学习继续调用 `ensureLearningNote`，写入原 `类型: 学习主题` 模板和学习根目录。
方向、所属能力、日期、状态仍是原有 Properties，目标写入既有学习目标章节。
项目继续调用 `createMengxuProject`，保留原项目 UUID、目录、Properties、项目任务章节。
没有新的进程存储格式、配置迁移、任务模型或用户数据改写。

状态统一为计划中 / 进行中 / 暂停 / 已完成 / 归档。
统一入口新建学习使用规范状态；读取侧继续兼容旧学习中为进行中。

## 清理与兼容边界

移除旧 `NewProjectModal`，学习专用新建表单仅保留学习资源/能力用途。
移除现代 Board source 的创建回调及菜单函数，左栏只有筛选列表，无空 footer。
`po-add-btn`、`po-cal__new` 仍供原作者 legacy 工具使用，因此不删除其共享样式。
快速任务预览、Embedded Tasks、进程详情、Project adapter、styles.css 均无改动。

## 验证

- `npm run check`：build / typecheck / test 全部通过，434 项原测试 + 24 项新增 = 458 项。
- 新增回归覆盖导航、无侧栏/日历创建入口、唯一 Modal、类型切换、两类保存、规范状态、旧状态读取、同名/竞态保护和预览无新建按钮。
- Obsidian 实机从顶部创建两份标记测试内容：学习与项目都写入正确 Markdown；项目不写所属能力。
- 首页、进程、收件箱入口均直达统一表单，无二级菜单或重复 Modal。
- 进程左栏、日历日期详情、日历双击均不再创建；明暗主题及 760px 窗口未见表单横向溢出。
- 测试笔记清理到 Vault 外的恢复备份；用户原笔记、目录和 data.json 以备份哈希核对。
