# 进程系统 v1

进程是只读汇总，不是新的存储格式或目录。

| 来源 | 纳入条件 | 任务范围 | 打开方式 |
| --- | --- | --- | --- |
| 学习 | `01-学习与资料/` 内 Properties `类型: 学习主题` | 同一笔记 `## 学习任务` | 学习进程详情；编辑入口打开原笔记 |
| 项目 | `03-项目与作品/` 内显式 `类型: 项目`，由现有 scanner 识别 | 同一笔记 `## 项目任务` | 现有梦序项目详情 |

资源、能力笔记、旧 Projects/TaskStore 不自动成为进程；不跨来源汇总同名任务。

## 只读适配

`Process` 包含 id、name、processType、status、rawStatus、direction、可选 startDate/dueDate、sourceFile、taskTotal/taskCompleted/taskPending、progress。

项目沿用 UUID；无 UUID 旧正式项目回退到路径定位。学习以来源路径作为运行时身份，不向笔记写入新 ID。Board 始终按完整路径识别卡片，允许学习和项目同名。

`progress = taskCompleted / taskTotal`；无任务为 `null`，UI 显示「暂无任务」。进度不表示能力掌握度、学习掌握度或项目质量。

## 状态与日期

- 五个统一状态：计划中、进行中、暂停、已完成、归档。
- 旧学习状态只读映射：学习中 → 进行中；待学习/排队中 → 计划中；已暂停 → 暂停；已学完 → 已完成；已归档 → 归档。
- 未填写/未识别状态暂归计划中，原值仍保留，学习详情显示映射说明，不重写 Properties。
- 当前学习和方向主题排序兼容「学习中」与「进行中」。
- 学习主题新模板仅增加空的开始/截止日期和学习任务章节；旧笔记无需迁移。
- 日历/甘特只投影进程的日期。无日期、非法日期或开始晚于截止的范围不绘制；仍可在列表/看板查看。有一个有效日期时显示单日，不补造范围。
- 不投影 Embedded Task 日期、不生成甘特子任务；时间条只读，日期通过来源笔记编辑。

## 页面与兼容

- 原 ProjectBoard 侧栏、卡片、状态列、表格、四个 Tab、月历和甘特几何实现继续复用；增加类型筛选和轻量文字标签，不新增视觉系统。
- 类型与状态筛选组合生效，选择/筛选仅保存在页面会话，不写 data.json。
- 新建菜单路由到现有学习主题 Modal 或现有项目 Modal，不引入第三套创建逻辑。
- 首页「进程与日程」沿用三行容量，进行中优先、计划中补位；月历/甘特入口进入同一个进程 Board。当前学习、作品与内容、人生方向详情保留。
- 学习详情从当前 Markdown 快照显示目标、任务、当前资源、下一步、实践。任务勾选继续调用 EmbeddedTaskStore；关联资源使用已有明确主题 Properties，重名歧义不猜测。
- 技术 View ID、插件 ID、目录、项目数据格式、Legacy 工具不变。

## 验证

保留 330 项基线测试，新增 48 项模型、类型/状态、进度、日期、同名甘特、混合 Board、新建菜单、详情路由/checkbox 等回归，共 378 项。运行 `npm run check` 与 `node --check main.js`。

实机以独立测试学习主题（1/3）和项目（2/4）验证四视图、组合筛选、详情、首页和 checkbox 写回/还原；检查明暗主题及窄窗口外层无溢出。原生新建菜单可见，保存验证使用它绑定的原 Modal 回调，不修改系统键盘权限。测试完成后移出全部临时笔记，保留 Vault 外恢复副本；原笔记和 Custom data.json 进行前后 SHA-256 比较。
